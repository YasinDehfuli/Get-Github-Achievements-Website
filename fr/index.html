Débloquez vos succès GitHub.

Les succès sont les badges que GitHub épingle sur votre profil quand vous faites certaines choses, comme fusionner des pull requests ou répondre à des questions. Ce site vous montre exactement comment obtenir chacun d'eux.

Succès à obtenir

Sept badges à obtenir dès aujourd'hui, du plus rapide au plus difficile. Ouvrez un guide pour voir toutes les étapes.

FacileEn solo~1 minute

Quickdraw

Fermez une issue ou une pull request dans les 5 minutes suivant son ouverture.

Voir les étapes (4)

  1. Vous devez créer un nouveau problème ou une demande d'extraction dans le référentiel de votre choix.

  2. Maintenant, vous devez écrire un titre et laisser un commentaire (si vous le souhaitez). et puis . Cliquez sur le bouton Soumettre un nouveau problème.

  3. Écrivez le commentaire de votre choix (vous pouvez également fermer le problème ou la demande d'extraction sans commenter.), puis cliquez sur Fermer le problème / fermer la demande d'extraction.

  4. Terminé, vous pouvez maintenant voir cette réalisation Quickdraw dans votre liste de réalisations.

FacileRequiert un 2e compte

YOLO

Fusionnez une pull request sans revue, alors qu'un relecteur a été demandé.

Voir les étapes (9)

  1. Tout d'abord, vous devez ouvrir le référentiel et accéder aux paramètres.

  2. Deuxièmement, vous devez vous rendre dans la catégorie des collaborateurs et dans cette section, inviter un compte auquel vous avez accès au référentiel.

  3. Troisièmement, vous devez ajouter une nouvelle branche à votre référentiel.

  4. Maintenant, vous devez ajouter un fichier à la nouvelle branche que vous avez créée.

  5. Ajoutez le fichier et validez sa description et validez enfin vos modifications

  6. Cliquez sur le bouton vert, comparez et tirez la demande.

  7. Ajoutez la personne invitée à l'étape 2 en tant que réviseur et créez une demande d'extraction.

  8. Enfin, vérifiez que votre réviseur, puis cliquez sur Merge pull request.

  9. Terminé, vous pouvez maintenant voir cette réalisation Yolo dans votre liste de réalisations.

MoyenRequiert une fusion

Pull Shark

Faites fusionner 2 pull requests.

Niveaux supérieurs à 16, 128 et 1024 pull requests fusionnées.

Voir les étapes (5)

  1. Vous devez obtenir un fork à partir d'un référentiel (vous pouvez forker n'importe quel référentiel de votre choix).

  2. Lors de la création de votre référentiel forké, vous devez apporter des modifications au référentiel forké (toutes les modifications telles que l'ajout d'un nouveau fichier ou la modification des codes !), Après cela, vous devez accéder à l'onglet de demande d'extraction .

  3. Cliquez sur le bouton créer une pull request .

  4. Vous pouvez maintenant voir le texte vert capable de fusionner, ce qui signifie que vous pouvez fusionner votre demande extraite. Cliquez donc sur le bouton Créer une demande d'extraction pour créer votre demande d'extraction avec succès. Ensuite, vous devez attendre que votre demande soit fusionnée par le créateur du référentiel.

    Vous avez besoin de 2 demandes de tirage fusionnées pour obtenir le succès Pull Shark

  5. Terminé, vous pouvez maintenant voir cette réalisation Pull Shark dans votre liste de réalisations.

MoyenRequiert un co-auteur

Pair Extraordinaire

Co-signez un commit dans une pull request qui est fusionnée. Vous et votre co-auteur l'obtenez tous les deux.

Niveaux supérieurs à 10, 24 et 48 pull requests co-signées fusionnées.

Voir les étapes (6)

  1. Vous devez installer GitHub Desktop et cloner votre référentiel à partir d'Internet. (si vous avez trouvé une erreur, vous devez ajouter votre référentiel à partir de votre fichier de référentiel interne)

  2. Clonez votre lien HTTPS de référentiel et insérez-le dans la zone de texte URL.

  3. Pas besoin d'utiliser la boîte de filtre, cliquez simplement sur Nouvelle branche et Créer une nouvelle branche pour votre référentiel

  4. Ajoutez un résumé dans votre zone de titre, puis ajoutez une description, enfin ajoutez un co-auteur par nom d'utilisateur GitHub (vous devez simplement valider un fichier dans votre référentiel (ne poussez pas les fichiers)).

    Vous préférez la ligne de commande ? Ajoutez plutôt cette ligne à la fin de votre message de commit :Co-authored-by: Their Name <their-email@example.com>

  5. Vérifiez maintenant votre référentiel sur GitHub et ajoutez des cessionnaires, puis cliquez sur le bouton Fusionner la demande d'extraction (la paire extraordinaire donnera aux deux comptes (vous et co-auteur)).

  6. Terminé, vous pouvez maintenant voir cette réalisation paire extraordinaire dans votre liste de réalisations.

DifficileRequiert d'autres personnes

Starstruck

Possédez un dépôt qui atteint 16 étoiles. Ça compte même si vous transférez le dépôt plus tard.

Niveaux supérieurs à 128, 512 et 4096 étoiles.

Voir les étapes (2)

  1. Vous n'avez besoin que de 16 étoiles pour chaque projet enregistré sous votre nom d'utilisateur. Recevez d'autres utilisateurs de votre organisation ou de votre référentiel .

  2. Terminé, vous pouvez maintenant voir cette réalisation Starstruck dans votre liste de réalisations.

DifficileRequiert d'autres personnes

Galaxy Brain

Faites accepter 2 de vos réponses dans les Discussions d'un dépôt public.

Niveaux supérieurs à 8, 16 et 32 réponses acceptées.

Voir les étapes (5)

  1. Ouvrez l'onglet Discussions de n'importe quel dépôt public et choisissez la catégorie Q&A (ou toute autre catégorie où une réponse peut être marquée). Les réponses publiées sur le forum officiel GitHub Community ne comptent plus, car GitHub y a désactivé les succès.

    Attention : les réponses sur le forum Community de GitHub ne comptent plus. GitHub y a désactivé les succès.

  2. Vous devez maintenant trouver les questions sans réponse dans toutes les catégories de votre choix. et répondre aux questions.

  3. Écrivez la réponse correcte à la question (votre réponse doit être la meilleure réponse possible pour être sélectionnée comme réponse soumise par le concepteur de la question).

  4. Vous avez besoin de deux réponses soumises dans toutes les catégories pour lesquelles vous souhaitez obtenir le succès Galaxy Brain

  5. Terminé, vous pouvez maintenant voir cette réalisation Galaxy Brain dans votre liste de réalisations.

FacilePayant

Public Sponsor

Soutenez un développeur open source via GitHub Sponsors.

Voir les étapes (5)

  1. (Vous devez d'abord savoir, pour obtenir ce badge, vous avez besoin d'une carte de crédit et donner de l'argent). Ensuite, vous devez d'abord ouvrir la page des sponsors GitHub, puis cliquer sur le bouton Voir vos principales dépendances.

  2. Vous pouvez voir une liste de développeurs que vous pouvez leur donner ici. (Vous pouvez être parrainé par tous les utilisateurs de GitHub qui ont un bouton sponsorisé sur leurs pages.)

  3. Après avoir trouvé une personne à parrainer. vous pouvez voir une page pour sélectionner le montant que vous souhaitez donner par mois.

  4. Il y a un formulaire de paiement ici, une fois votre paiement terminé. Vous pouvez voir votre badge dans votre profil (dans la version bêta, 30 pays ont des méthodes de paiement pour l'instant).

  5. Terminé, vous pouvez maintenant voir cette réalisation de sponsor public dans votre liste de réalisations.

Teintes de peau 👋🏽

Certains badges, comme Quickdraw et Starstruck, suivent la teinte de peau de vos emoji. Changez-la dans vos paramètres d'apparence.

Masquez-les si vous voulez

Pas fan des badges ? Vous pouvez désactiver les succès sur votre profil depuis vos paramètres de profil.

Pour les règles officielles, consultez la documentation GitHub sur l'affichage des badges sur votre profil.

Jouez fair-play 🏁

Ce guide est là pour vous apprendre comment fonctionnent les succès. Merci de respecter les conditions d'utilisation et les règles de la communauté GitHub : ne spammez pas d'autres projets juste pour collectionner des badges. Le meilleur moyen de les obtenir est de participer à de vrais projets et d'aider les autres.
